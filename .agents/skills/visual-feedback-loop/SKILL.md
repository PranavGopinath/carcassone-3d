# Visual Feedback Loop (Prompt 2)

Prerequisites: Prompt 0 and Prompt 1 have already run and will not be re-run. Every model call goes through `scripts/lib/orchestrator.mjs` (trace, budget caps, rate limiting, scheduling, caching, `ORCH_FAKE=1`). The target app passes its own build gates. Anything this loop needs that those prompts didn't build, this prompt builds (see §0); never assume a capability exists without checking the code.

## Primary goal (read this first; it decides every trade-off)

In strict priority order:

1. **The 2D view is clean.** No flicker, shimmer, z-fighting, tile or object pop-in, seams or gaps between tiles, jittering or swimming textures, shifting edges, misaligned or missing features, clipped or overlapping UI, or frame-to-frame instability. A static 2D scene must be pixel-stable. A 2D action (placing a tile, dropping a meeple, scoring) must animate smoothly with no instant changes.
2. **The 2D↔3D transition is smooth and complete.** In both directions, every tile, feature and object that exists before the transition exists in every frame during it and after it, in the right place. Nothing vanishes, appears at once, teleports, flashes, stretches wrongly, or lags behind the camera. The camera and the morph follow continuous, eased paths with no jerk. The first frame after the transition looks like the last frame before it, from the new view.
3. **Realism.** The board reads as a photographed physical miniature like `diorama-style-ref.png`, in both views.

Items covering goals 1 and 2 are **tier 1** (`tier: 1` in the rubric). Realism and polish are tier 2. **A change that improves tier 2 but regresses tier 1 is worse, always.** When the budget or time is limited, tier 1 gets the attention first. The loop is not done while any tier 1 item is open, however good the realism looks.

## 0. Upgrade the orchestrator first

Before writing loop code, read `scripts/lib/orchestrator.mjs` and add whatever of the following is missing, with offline tests in `tests/orchestrator.test.ts` (existing tests must keep passing):

1. **Deadlines.** Long or `thinking: "high"` calls run with `background: true` and poll `ai.interactions.get(id)` with exponential backoff under a hard per-call deadline (`pollTimeoutMs`, default 90s, configurable per call). A call past its deadline is cancelled and retried with backoff like a 5xx; it never hangs the process.
2. **Persistent spend.** Initialize cumulative cost and call counts from `runs/orchestrator/trace.jsonl`, so budget caps hold across processes.
3. **`runToolLoop({ role, tools, input, maxToolCalls, deadlineMs, previousInteractionId })`.** A function-calling loop on the Interactions API: send the tool declarations, execute each returned function call through the caller's handler, return the result, and repeat until the model calls `finish` or a cap is hit. Each turn is traced and metered. Under `ORCH_FAKE=1` it replays scripted tool-call sequences so the patcher is testable offline.
4. **Rate limiting and 429 handling (a 429 must never fail or end a run).**
   - A shared **token-bucket limiter** for requests per minute and estimated tokens per minute (`rateLimit.rpm`, `rateLimit.tpm` in the config; estimate tokens from text length plus a fixed cost per image and per video second). Every call waits for the limiter before it is sent. Start conservative; the limits adapt (below).
   - **Classify** each 429/`RESOURCE_EXHAUSTED`: per-minute (rate) or per-day/per-project (quota), from the error body, quota metric name and `Retry-After`/`retryDelay` if present. If unclear, treat it as a rate limit.
   - **Rate-limit 429:** honor `Retry-After`/`retryDelay` when given; otherwise wait with exponential backoff plus full jitter (base 2s, cap 120s). A 429 does **not** count against a call's failure-retry limit; it only counts toward the stall timer (§4.7). The call is retried until it succeeds or the stall limit is hit.
   - **Quota 429:** pause all dispatch. If the reset time is known or estimated and is within `limits.maxStallMs` (default 6h), sleep until then and continue. Otherwise throw a typed `QuotaExhausted` error that the loop turns into a checkpoint and a resumable exit (§4.7). Never retry a quota error in a tight loop.
   - **Circuit breaker:** 3 rate-limit 429s inside 60s open the breaker: pause all dispatch for the cooldown, then resume at half the previous limits.
   - **Adaptive concurrency (AIMD):** every 429 halves the effective concurrency and request rate (floor 1); every 20 consecutive successes add 1 back, up to the configured caps. Log every change to the trace.
   - Under `ORCH_FAKE=1`, support `ORCH_FAKE_429=<fraction>` and `ORCH_FAKE_QUOTA_AFTER=<n>` to inject rate and quota errors, with a fake clock so tests don't really sleep.
5. **Scheduler.** `orchestrator.schedule(role, priority, fn)` is the only way any script runs model calls concurrently; no script hand-rolls `Promise.all` around raw calls. It enforces `concurrency.global` plus per-role caps (`concurrency.judges`, `.pairwise`, `.patchers`), the limiter above and the budget cap. Priorities, highest first: escalation and patcher turns, re-asks on uncertain items, **tier 1 judging (2D stability, transitions)**, pairwise, other judges, golden set. A lower-priority task never starves a higher one, and the scheduler never starts a call that would exceed `budgetUsd` (it rejects with `BudgetExhausted`, which ends the run cleanly).
6. **Verdict cache.** Cache key = sha256 of model, role, prompt text, schema, rubric hash and the sha256 of every media input. Store under `runs/orchestrator/cache/`. A hit returns the stored response with `cached: true` in the trace and no spend. Never cache `uncertain` or errored results, and bypass the cache for the golden set. Also cache Files API uploads by file hash and reuse the file handle until it expires, so identical clips are never re-uploaded.

The loop runs with **no human in it**. Implement the whole spec; where something is hard (the golden set, the patcher's tool loop, tie-breaks, the rate limiter, transition measurement), build the real thing rather than a stub that makes a check pass.

## Hard rules

1. **The evaluation is immutable; the product is not.** During a run the patcher may edit anything in the worktree **except** `protectedPaths` (rubric, references, loop scripts, gates, config, skills) and the **baseline tests** (every file under `tests/` tracked at the run's start commit). It may **add** new tests under `regressionTestDir`. After every patcher turn, `git diff --name-status <startCommit>` must show no change to a protected path or baseline test; if it does, the iteration is rejected and reset, whatever the judges say.
2. **Never record in real time.** Freeze the app's clock, render each frame by time, and screenshot it. Video is stitched from those frames.
3. **Measurements beat opinions.** A failing hard check (`audit:*`, `frameDiff`, `blankFrame`, `stepErrors`, `stability2d`, `transitionContinuity`, `cameraSmoothness`) fails its rubric item whatever a judge says. An `audit:<field>` source passes when the field is `true`, `0`, an empty array, or an object whose `ok` is `true`; anything else fails, with the field's value and the audit's `details` as evidence. If `audit()` doesn't return a field the rubric names, the item fails with a defect asking the patcher to add that measurement to the app's audit.
4. **The rubric is the goal, and it has two kinds of item** (see §2). `defect` items ask "is something broken?"; `fidelity` items ask "how far is this from the reference?". The loop is not done while either kind has open failures, and never while a tier 1 item is open. Passing every defect item on art that looks nothing like the references is not success.
5. **`GEMINI_API_KEY` is read only by Node** (`node --env-file=.env`). Never use a `VITE_` prefix and never log it.
6. **High effort for every verdict.** Every judge, pairwise, patcher and escalation call uses `gemini-4-argon` with `thinking: "high"` and media at `media_resolution` high. Pass both explicitly on each call. **Never lower the thinking level, media resolution or model to save time, money or to avoid a 429.** Speed comes from concurrency, caching, reuse of unchanged results and early exits (§0.5, §0.6, §2, §4); rate limits are handled by pacing and waiting (§0.4). The budget cap ends the run instead.
7. **Nothing blocks, and nothing dies on a 429.** No stdin prompts, no waiting on a person. Every model call has a deadline (§0.1). A stalled call is cancelled and retried; a rate-limited call is paced and retried (§0.4). The run only stops for the reasons in §4.5, or checkpoints and exits resumably when a quota stall exceeds `limits.maxStallMs` (§4.7).
8. **Never trust model-invented IDs as keys.** Defect IDs are assigned by code when verdicts are merged: `<judge>-<itemId>-<n>` (e.g. `still-M2-1`).
9. **Every view, every iteration.** Each iteration captures and judges every view in `views` (e.g. `2d` and `3d`): the gameplay scripts in each view, and at least one canvas shot and one page shot per view. An item with `views` is judged separately in each view and passes only if it passes in all of them. Never skip capturing a view. **Judging** may reuse the previous verdicts for a shot or clip only when its pixels are within tolerance of the capture those verdicts were made on, in the same view, under the same rubric hash (§2, "Incremental judging"); anything that changed is judged fresh. **Tier 1 evidence (2D stability and transitions) is always captured and measured fresh every iteration**; only its model verdicts may be reused, and only when the frames are pixel-identical within tolerance.
10. **Gameplay is graded, not just the cinematic.** The loop drives real game actions and real UI clicks through scripted timelines (§1.6). A render that looks right in a fixed camera flight but breaks when a tile is placed, a score changes or the view is toggled has not passed.
11. **Scope comes from the config.** The loop improves what the config's `inScope` lists. For this project that is the 3D board (terrain, slab, water, buildings, props, meeples, lighting and materials on them), the environment it sits in (sky, clouds, background), its 2D counterpart, the 2D↔3D transition, **and the game's UI: HUD, panels, menus, buttons, typography and overlays**. Everything in the config's `outOfScope` (default: empty) belongs to someone else: judges ignore it when grading other items and the patcher is told not to change it. Checks that only an out-of-scope change could fix are `reportOnly` items (§2). Enforce it two ways: a diff touching `outOfScopePaths` is rejected like a protected-path violation, and every pairwise call also asks whether anything out of scope changed between the two renders; a confirmed (both orders) out-of-scope change makes the iteration worse.
12. **The 2D and 3D views show the same game.** Every tile, feature and object visible in one view must exist, in the same place, in the other: a house drawn on a 2D tile must stand on that tile in 3D, and nothing may appear in 3D that the 2D tile doesn't show. The tile spec and game state are the source of truth: when the views disagree, fix whichever view departs from the spec, and if both do, fix both. This holds **in every frame of the transition**, not just before and after it.
13. **Realism is the style target (tier 2).** The board should read as a photographed physical miniature like `diorama-style-ref.png`: real materials with surface variation, soft natural light and shadow, believable scale and density. Flat colors, untextured primitives and low-poly game art are fidelity gaps, not acceptable style choices. The patcher creates materials **procedurally** (shader noise, generated canvas/texture maps, normal and roughness maps, baked AO, environment lighting, soft shadows) or from assets already in the repo. It never downloads external assets, never adds dependencies the config doesn't allow (`allowedDependencies`), and never copies a reference image into the app. **Realism must never be bought with 2D or transition glitches:** a new texture, shadow or lighting technique that adds flicker, shimmer, swimming, pop-in or a morph discontinuity is rejected as a tier 1 regression.
14. **The UI must look like a shipped, professional product (tier 2).** Every page and HUD state graded in a page shot or gameplay frame has a consistent type scale and font pairing, a spacing grid, alignment, sufficient contrast, coherent iconography, designed hover/active/disabled states, no overlap, clipping or overflow at the configured viewport(s), and a visual language that matches the diorama (materials, palette, lighting). It is graded by `fidelity` items against `ui-style-ref` (if the config supplies one, otherwise against the diorama reference for palette and material feel) and by `defect` items.
15. **2D is temporally stable (tier 1).** With no game action and no camera input, consecutive 2D frames are pixel-identical within `stability.tolerance`. Any difference is a defect with the cell, the frame and the size of the change. Anti-aliasing shimmer, texture crawl, shadow flicker, sub-pixel jitter, random or time-driven noise, and tiles that shift by a pixel are all failures. During a 2D action, the only pixels that may change are those of the object being animated and its shadow, and the change must be gradual.
16. **The 2D↔3D transition is continuous (tier 1).** Captured densely (§1.12), in both directions, from several game states (empty board, mid-game board, board with every feature type). In every transition frame: every tile and object in `getState()` is present (audit count per tile equals the state); no object's screen position moves faster than `transition.maxObjectSpeed` or changes direction abruptly; the camera path has bounded jerk; opacity, scale and morph parameters change monotonically and eased, never in a single frame; no frame is blank, partially drawn or shows a different board; and the last frame before the switch and the first frame after it differ by no more than a normal frame-to-frame step.

## 1. Capture: `capture.mjs`

1. Start `devCommand` once per run **and once per candidate worktree** (§3.7), each on its own free port. Load the page fresh for every capture. **No HMR**: stale WebGL state gives wrong frames.
2. Use Playwright Chromium (`npx playwright install --only-shell chromium`) with the configured viewport and `deviceScaleFactor`, and GPU flags (macOS: `--use-angle=metal`). Read the renderer string via `WEBGL_debug_renderer_info`. **Fail** on SwiftShader or any software renderer.
3. Before frame 0, wait for fonts (`document.fonts.ready`) and textures (the `ready` hook if present). Check that `inspect` mode drives `performance.now`, `Date`, `requestAnimationFrame` and `Math.random` from `t` and the seed. Anything that animates by wall clock is a determinism defect.
4. For each `t` at `timeline.fps`, call `renderAt(t)` and take a `page.screenshot` clipped to the canvas. Don't use `toDataURL` on the WebGL canvas (it needs `preserveDrawingBuffer`); a 2D canvas returned by a hook, like the tile sheet, can be read with `toDataURL`.
5. Take the configured canvas `shots` and the tile sheet. Then take each `pageShots` entry: set its `view`, `renderAt(t)`, and take a **full-page** screenshot (not clipped), so the HUD and overlays are graded. Save `audit()` output plus page console errors to `audit.json`.
6. **Gameplay capture.** For each script in `gameplay.scripts`, and for each view in `gameplay.views` when the script has `perView: true` (otherwise once, from its `startView`):
   1. Reload the page, call `setView(view)` instantly, and reset the play clock with `playAt(0)`.
   2. Walk time from 0 to `duration` at `gameplay.fps`. Before rendering the first frame at or after a step's `at`, apply the step: `call` invokes that hook on `window[global]` with `args`; `click` dispatches a real Playwright click on the selector, so HUD wiring is tested too. Then `playAt(t)` and take a **full-page** screenshot (gameplay is graded with its HUD).
   3. After each step settles (the frame before the next step), run `audit()` and keep its fields per step, so `audit:*` sources can be checked at every step of play, not just on a static board.
   4. Record any console error or exception thrown during a step as a `stepErrors` hard-check failure, with the step and time. Also record as `stepErrors`:
      - a **no-op step**: a step after which neither `getState()` nor the frame changed (e.g. an unknown fixture name that silently loads the same board, or a bot move with no tiles left)
      - a failed **expectation**: a step's `expect` is a JS expression over `before` and `after` (`getState()` snapshots around the step, each with a `view` field from the `getView` hook); a script's `expect` is one over `start` and `end` (around the whole script), `startView`, and `views` (the `getView()` value recorded at every captured frame). Either evaluating to false is a failure naming the expression.
   5. Run `blankFrame` and `frameDiff` on the script's frames, and stitch `play-<scriptId>-<view>.webm`.
   Gameplay animation (tile drop, meeple drop, highlights, score popups, view morphs) must be driven by `playAt(t)`, never wall clock; if two captures of a script differ beyond tolerance, report a determinism defect.
7. **Hard checks:**
   - `blankFrame`: any frame that is nearly a single color.
   - `frameDiff`: compute the changed-pixel fraction per consecutive pair **globally and per cell** of a `frameDiff.grid` (e.g. 8×8). Flag a spike when either (a) a cell's fraction exceeds `spikeFactor` × that cell's segment median, or (b) the **second-order** change `|d(t) − d(t−1)|` exceeds `spikeFactor` × its segment median. Smooth camera motion raises the first-order diff everywhere but keeps the second-order diff low; pop-in and z-fighting spike both locally and in the second order. Ignore frames on either side of a segment boundary. Do **not** exempt frames after a gameplay step: an intended change (a tile dropping in) is animated over several frames and stays under the second-order threshold, while a tile that pops in at once is exactly what this check must catch.
   - `stepErrors`: any console error or exception, no-op step or failed expectation during a gameplay step.
   - `stability2d`, `transitionContinuity` and `cameraSmoothness`: defined in §1.12.
   - Run `frameDiff`, `blankFrame` and the determinism comparison on the **canvas region with DOM overlays masked out** (the bounding boxes of elements drawn over the canvas). Full-page frames are for the judges; HUD text changing instantly when the score updates is not a pop-in, and an out-of-scope HUD timer must not make the board look nondeterministic.
8. Stitch frames with ffmpeg (`@ffmpeg-installer/ffmpeg` if there is no system ffmpeg). If stitching fails, continue with stills. Stitching runs in the background while the next capture unit proceeds.
9. Two captures of the same commit must match within a small per-pixel tolerance (on the masked canvas region, as above).
10. Export `captureShot(workDir, shotId | {t} | {script, view, t})` as a cheap single-image path. Page shots and gameplay frames come back **full-page**, exactly as the judges see them, so HUD changes can be previewed. The patcher's `preview` tool uses it (§3). Also export `captureTransition(workDir, {state, direction, p})` and `captureStability(workDir, {view, state})` so the patcher can test tier 1 changes cheaply.
11. **Parallel capture.** The capture units (cinematic timeline, canvas shots, page shots per view, 2D stability sequences, transition sequences, and each gameplay script × view) are independent. Run them in a pool of `capture.workers` workers (default 2; the GPU is the limit), each in its own browser context and page against the same dev server, never sharing a page between units. Each unit reloads fresh, seeds itself and writes only to its own output folder. Emit a `unit-captured` event as each unit finishes so judging can start on it immediately (§2, "Streaming"). Tier 1 units are queued first. The determinism comparison (item 9) must still pass with the pool running; if parallel capture makes a unit differ from a serial capture beyond tolerance, lower `capture.workers` automatically and report a determinism defect.
12. **Tier 1 capture and measurement: 2D stability and the 2D↔3D transition.** These are the most important captures in the loop.
    1. **2D stability sequence** (per `stability.viewports` and per game state in `transition.states`): load fresh, `setView("2d")`, then capture `stability.frames` (default 60) consecutive frames with **no input and the play clock advancing**, plus a second sequence of 30 frames after a settled tile placement. `stability2d` (hard check) computes the changed-pixel fraction and the maximum per-pixel difference between every consecutive pair, globally and per `frameDiff.grid` cell, on the canvas with overlays masked. In the idle sequence every pair must be within `stability.tolerance` (default: zero changed pixels beyond a tiny noise floor); any flagged pair is a defect naming the frame, the cell and the magnitude. Also compare frame 0 with frame N: slow drift is a defect. Run the idle sequence twice with different play-clock offsets; the frames must match each other too (time-driven noise is a defect).
    2. **Dense transition capture** for each state in `transition.states`, each direction in `transition.directions` (2D→3D and 3D→2D), and also a mid-transition **reversal** (start 2D→3D, reverse at p=0.5): drive `setTransition(p)` or the hook the app uses for the morph, from 0 to 1 at `transition.fps` (default 60) over `transition.duration`, **never by wall clock**, taking a canvas screenshot at every step and a full-page screenshot at 5 evenly spaced points. At **every** step also call `getObjects()` and keep the full per-tile object list, screen positions and visibility, camera position and orientation.
    3. `transitionContinuity` (hard check), evaluated on those per-frame records:
       - **Presence:** the set of tile and object IDs in `getState()` equals the set in `getObjects()` at every frame, all visible with opacity above a floor and scale above a floor. Any object missing, hidden or at zero scale for any frame, or present that isn't in the state, is a failure naming the object, the tile and the frame (this is the "missing components when switching" bug).
       - **Position continuity:** per object, screen speed between frames stays under `transition.maxObjectSpeed` and its acceleration is bounded; a position jump (teleport) fails.
       - **Parameter monotonicity:** morph progress, opacity, scale and height are monotonic, eased functions of `p`; a single-frame jump above `transition.spikeFactor` × the sequence median of the per-frame change fails.
       - **Seam:** the pixel difference between the last frame before the view flag flips (or any internal switch, such as a material or renderer swap) and the first frame after it must be within `transition.spikeFactor` × the median frame-to-frame diff; a visible swap pop fails.
       - **Pixel spikes:** apply the §1.7 `frameDiff` global, per-cell and second-order tests to the transition frames with a tighter `transition.spikeFactor`, and **no segment-boundary exemption inside the transition**.
       - **Endpoints:** frame p=0 matches the stand-alone view A within tolerance and p=1 matches the stand-alone view B (compare with the stability sequence frames), so the morph begins and ends exactly on the real views.
       - **Reversal:** reversing at p=0.5 continues from the current pose with no jump.
    4. `cameraSmoothness` (hard check): from the recorded camera poses, compute velocity, acceleration and jerk per frame. Fail on any frame whose jerk exceeds `transition.maxJerk`, any direction flip that isn't intended, and any non-continuous orientation (quaternion flip or gimbal pop).
    5. Stitch `transition-<state>-<direction>.webm` at `transition.fps` and also build a **labelled filmstrip** (every 5th frame, with the frame index and `p`) per sequence, for the judges. Also write a `transition-report.json` with the worst frames and objects per check.
    6. Capture each tier 1 unit twice per iteration (fresh page each time); if the two captures differ beyond tolerance, report a determinism defect (a tier 1 failure).

## 2. Judges: `judge.mjs`

Both judges use `gemini-4-argon` and the `judge_a`/`judge_b` roles. They can't write files. Write timestamps as `MM:SS`. Every call goes through `orchestrator.schedule` (§0.5).

**Prompt layout:** precede every image with a one-line text label (`[Image 3: waterfall-macro, full shot]`, `[Image 4: reference diorama-style-ref]`), and put all grading instructions **after** the media.

### Streaming, concurrency and incremental judging

- **Streaming.** Start judging each capture unit as soon as it emits `unit-captured`; don't wait for the whole capture. Tier 1 units are judged first. All judge calls for an iteration are independent and are dispatched together through the scheduler; judge_a and judge_b run concurrently. Re-asks and pairwise calls are dispatched as soon as the verdicts they depend on exist; both orders of a pairwise call run concurrently.
- **Hard checks first.** When a unit's hard checks finish, evaluate them before spending on its judges. If hard checks already make the whole iteration worse than the best (§4.3), including any tier 1 regression, or hard rule 1/11 is violated, skip the remaining judge calls for that candidate, mark it worse, and move on.
- **Incremental judging.** For each shot, page shot, crop and gameplay clip, compare it with the same unit from the iteration that produced the best-so-far verdicts, in the same view. If the pixels are within the capture tolerance and the rubric hash is unchanged, **reuse the stored verdicts** (mark `reused: true`) instead of calling a judge. Judge every unit that changed, every unit touched by an open defect, and every `fidelity` shot touched by this iteration's diff. Never reuse an `uncertain` or failed-hard-check verdict. All views are still captured every iteration (hard rule 9).

### Item kinds

- **`defect`**: pass/fail. Hard sources decide; the judge covers what can't be measured. A fail must cite a `t` or shot plus a mark or region.
- **`reportOnly: true`** (either kind): judged and shown on the dashboard and in `summary.json` under "for the owner", but never sent to the patcher and never counted in pass counts, better/worse comparisons or the stop condition. Use it for checks on out-of-scope areas, so their bugs get reported to whoever owns them.
- **`fidelity`**: send the item's shot, then each of its `references`, then the item's `aspect`. The judge returns a ranked list of **gaps** (concrete, visible differences between render and reference for that aspect, each with severity and region) and a verdict that passes only when no `high` or `medium` gap remains. Tell the judge the reference shows **style, materials, lighting and density, not layout**: ignore differences in board shape, tile arrangement and terrain elevation that come from the game's rules. For UI aspects, tell the judge the reference shows **visual language and polish, not layout or content**. Every `high`/`medium` gap becomes a defect for the patcher.
- **`tier`**: every item has `tier: 1` or `tier: 2`. Tier 1 items are judged first, shown first on the dashboard, sent to the patcher first, and weigh more in §4.3.

### Judges

- **judge_a (motion):** one call per motion clip: the cinematic's `timeline.motionSegments` (clipped from `flight.webm` with `start_offset`/`end_offset`), every gameplay video (`play-<scriptId>-<view>.webm`), **and every transition video and 2D stability video** (§1.12). Upload via the Files API (cached by file hash, §0.6) and poll until `ACTIVE`. Use **static** processing, set `fps` near the capture rate, `media_resolution` high. With each clip send its step list as `MM:SS` labels ("00:02 bot places a tile", "00:05 click rotate"), so the judge knows what should happen when, and a labelled filmstrip of the frames around each `frameDiff`, `transitionContinuity` or `cameraSmoothness` flag (with the failing object or cell marked). Grade only the motion items for that segment and view. For transition clips, the judge's instructions are: list every moment where an object disappears, appears, jumps, flashes, stretches, lags, swaps materials or where the camera stutters; name the tile and the timestamp; and say whether the motion feels continuous and physically plausible. For 2D stability clips: list any flicker, shimmer, crawl, jitter, shifting edge or seam, even small ones, with the region.
- **judge_b (stills):** one call per shot group and view. Send the shot plus a high-resolution crop for each `crop` item (`crop: true` crops to the item's marks or the region a previous verdict cited; `crop: "<css selector>"` crops a page shot to that element). An item with a `shots` list gets every listed image, labelled. Turn audit findings into **numbered marks drawn on the image**, not raw JSON: an item's `marks: "<name>"` draws the positions in `audit().marks[<name>]` (`[{ shot, x, y, label }]`). If the audit has no positions for that name, send the image unmarked and add a low-severity defect asking the patcher to expose them. Send each item's `references`. For gameplay items with `at: "after-step"`, send the settled full-page frame after each step, labelled with the step. For 2D stability, also send **difference images** (amplified) between consecutive frames and the two-run comparison. For transitions, send the labelled filmstrip with the object marks drawn from `getObjects()`, so the judge can follow each tile's objects frame to frame.

### Cross-view consistency items

An item with `pairViews: true` is judged on matching 2D and 3D images side by side: for a shot item, the shots in its `shots` list (e.g. `board-2d` with `terrace-overview`); for a gameplay item, the settled 2D and 3D frames after each step of its script. **A `pairViews` item may also be applied to transition frames at p=0, 0.25, 0.5, 0.75 and 1, pairing each with the matching object marks.** Draw the same numbered tile marks (from the audit's `tileLabels`, the screen position of each tile in each image) on both images so the judge can match tiles. The judge lists, per tile mark, every object or feature present in one view and missing, moved or different in the other; each mismatch is a defect naming the tile, both views (or the transition `p`), and which view departs from the tile spec.

### Views

An item with `views` is resolved once per view; its stored result is `{ view: verdict }` and it passes only if every view passes. Items whose evidence exists only once (a cinematic segment like `rise`, a script with `perView: false` like `toggle`, a transition sequence, a `pairViews` item) are judged once; their `views` only declares which views they cover for the startup check. Each defect carries its `view`, and so does its ID (`motion-G1-3d-1`). A gameplay item's `segment` names a script; for `perView` scripts it is judged on that script's capture in each listed view. A `{view}` in an item's `shot` expands per view (`ui-{view}` → `ui-2d`, `ui-3d`).

### Merging verdicts

- Assign defect IDs in code (hard rule 8).
- If the judges disagree, or a judge says `uncertain`, re-ask once on a tighter crop and take the majority of three. **An item still uncertain after the re-ask is a fail.** Never coerce `uncertain` to `pass`.
- Both judges are the same model family: agreement corroborates, it doesn't validate. That's what the golden set is for.

### Pairwise

A separate call compares the best-so-far with the current iteration. Run it on **every shot touched by this iteration's defects plus every fidelity shot whose pixels changed, plus every tier 1 unit (2D stability and each transition) whose frames changed**, in every view they apply to, not a single global shot. Ask per item, never "which is better?" in general: for a `fidelity` item, send the item's `references` too and ask which render is **closer to the reference** for that item's `aspect`; for a `defect` item, ask which shows less of that defect; for a transition, ask which clip is **smoother and loses fewer objects**. Randomize which is A or B, ask in **both orders**, and count a winner only if it wins both times; otherwise it's a tie. Shots whose pixels are within tolerance of the best-so-far are ties without a call.

### Golden set (real, before the first live run)

The golden set measures whether the **vision judges** catch things, so hard checks are hidden from the judges for these cases. Include a cross-view case: remove one building or feature from one view only and confirm the consistency items catch it. Run the cases concurrently through the scheduler, with the cache bypassed.
1. **Injected defects.** Use the `injectDefect` hook (if the project has one) and capture-side perturbations (blank a frame, offset one mesh for one frame, duplicate a frame) to produce real broken captures: a floating prop, a blank morph frame, a hovering meeple, a frame of flicker, a pop-in, and in gameplay a tile placed with no drop animation. Also include UI cases (overlapping or clipped HUD text, a low-contrast label). **Tier 1 cases (the most important):** in 2D, a one-pixel tile shift for one frame, subtle shadow flicker, texture shimmer, a seam gap between two tiles, a tile that pops in; in the transition, an object that vanishes for 3 frames mid-morph, an object that teleports, a one-frame material swap pop, a camera stutter, a missing building at p=0.5, a reversal that jumps. Run judge_a/judge_b on them, in both views and directions.
2. **Fidelity calibration.** Grade each reference image as if it were the render (it must pass with no high gaps), and grade iteration 0's untouched draft (it must not pass if it visibly differs). A fidelity judge that passes both or fails both is broken; fix the prompt before running live.
3. **Tier 1 calibration.** Run the tier 1 judge prompts on clean captures as well (a stable 2D sequence and a smooth transition); they must pass. A tier 1 judge that flags clean captures, or misses the injected ones, is broken; fix the prompt before running live.
4. Record per-case results, recall, false positives and the real `interactionId` of every judge call in `runs/loop/golden.json`. A judge may fail a defect item without a hard check only for defect types it caught here.

## 3. Patcher: `patch.mjs`

The patcher is a **tool-using agent working inside a worktree**, not a single call that returns text edits.

1. **Runtime.** `runToolLoop` from §0.3. The loop runs headless from Node, so it can't use an IDE's native subagents; parallel agents are separate `runToolLoop` calls scheduled through §0.5.
2. **Tools** (all paths resolved inside the agent's own worktree; writes to protected paths or baseline tests are refused with a reason):
   - `list_files(dir)`, `read_file(path, startLine?, endLine?)` (returns numbered lines), `search(pattern, dir?)`
   - `write_file(path, content)`, `edit_file(path, search, replace)` (search must match exactly once; on 0 or 2+ matches return the matching line numbers)
   - `run(command)`: only the configured `acceptance` commands and `npx vitest run <path>`; returns exit code and the log tail
   - `preview(shotId | t | {script, view, t})`: builds and returns the current render of that shot, page shot (full page, HUD included), cinematic frame or gameplay frame (running the script's steps up to `t`) as an image, so the patcher can see its change before the full capture. For fidelity defects it returns the item's reference beside the render.
   - `check_transition(state, direction)`: runs the dense transition capture and the `transitionContinuity` and `cameraSmoothness` checks headlessly and returns the failing frames and objects, the per-frame object count, and a filmstrip. Use it to verify any transition fix before `finish`.
   - `check_stability(view, state)`: runs the 2D stability sequence and `stability2d` and returns the flagged frames and cells with amplified difference images.
   - `run_script(script, view)`: plays one gameplay script headlessly and returns its step errors, per-step audit and a filmstrip, for gameplay defects
   - `finish(report)`: ends the turn with a report per `schemas/patch-report.schema.json`
3. **Context at the start of each iteration (fresh conversation):**
   - open defects **ordered tier 1 first**, with their measurements, shot, region, and for fidelity gaps the matching reference image; for transition defects the failing frame, object, tile and `p`
   - the current image of each targeted shot
   - a file outline of `src/` (path, exported symbols, line counts); the agent reads what it needs
   - the scope and correctness rules it must respect: `inScope`, `outOfScope` and `outOfScopePaths`, `protectedPaths`, hard rules 11–16 (scope, 2D/3D consistency with the tile spec as source of truth, realism as the style target with procedural materials only, professional UI, 2D stability, transition continuity)
   - the rule that **tier 1 fixes come first and no tier 2 change may regress tier 1** (it must run `check_stability` and `check_transition` after any change to materials, lighting, shadows, camera, the morph or the renderer)
   - escalation plan and launch `--notes`, if any
   - `triedLedger`: the last 8 failed attempts, one line each (`defectId, files, ≤25-word change, outcome`)
   - for a parallel candidate, the list of defects assigned to **it** and the file areas other candidates are working on (so it avoids them)
   Leave out old diffs and judge prose.
4. **Working loop.** Address tier 1 defects first, then by severity; several per iteration is fine. For a defect that can be measured (geometry, camera framing, a seam, a pop-in, an object missing mid-transition, a jittering tile), **write a regression test first** under `regressionTestDir` (for example: every object in the state is present and visible at every transition step; the idle 2D scene is pixel-stable; the morph parameters are monotonic), make it pass, then `preview` the shot. For a fidelity gap, iterate with `preview` against the reference. Typical structural fixes for tier 1: drive every morph from one `p` with an easing curve, keep one scene graph for both views (never swap or rebuild objects at the switch), snap geometry to a fixed grid and use consistent depth bias or polygon offset to prevent z-fighting and seams, fix shadow-map and texel snapping to remove shimmer, remove all wall-clock and unseeded randomness, and cross-fade only with continuous opacity. Stop at `finish` or when `patcher.maxToolCalls` / `patcher.deadlineMs` runs out.
5. **Gate.** After the agent finishes, run hard rule 1's diff check, then `acceptance` (baseline tests + new regression tests). If acceptance fails, give the agent one more bounded turn with the log. If it still fails, reset to the iteration's start and record the attempt in `triedLedger`.
6. Commit as `loop iter <N>: <defectIds> <summary>`.
7. **Parallel candidates.** Each iteration runs up to `patcher.candidates` patcher agents at once (default 2, never more than `concurrency.patchers`).
   1. **Cluster in code, not by the model.** Group open defects by view, shot and aspect, then split the groups into disjoint sets, **tier 1 defects first and spread across candidates**, so no defect is assigned twice. Defects in the same file area (for example the morph code) go to the same candidate. If there are fewer groups than candidates, run fewer candidates. An escalated iteration (§4.4) runs a single candidate executing the escalation plan.
   2. **Isolate.** Each candidate gets its own worktree `wt/loop-<runId>-c<k>` on branch `loop/<runId>-c<k>`, created from the current best commit, with its own dev server and port, and runs steps 3–6 independently. Candidate agents never share files or processes.
   3. **Evaluate.** Each candidate passes its own gate, is captured (through the capture pool, tier 1 first) and judged (streaming, hard checks first) and compared with the best using §4.3.
   4. **Adopt.** Adopt the best candidate that is **better** than the best so far. Then try to cherry-pick the other better candidates onto it; if they apply cleanly, run gate, capture and judge on the combination as one more candidate, and adopt it only if it beats the best single candidate. Clean up all candidate worktrees and branches.
   5. **Ledger.** Record every non-adopted candidate in `triedLedger`.
   All candidate spend counts against `budgetUsd`.

## 4. Loop: `run.mjs`

```
node --env-file=.env scripts/loop/run.mjs [--max-iterations N] [--budget-usd X] [--notes "..."] [--resume <runId>]
```

1. Work in worktree `wt/loop-<runId>` on branch `loop/<runId>`, from the config's `baseBranch` at its current tip, using the orchestrator's worktree helpers. Record `startCommit`.
2. Iteration 0 captures and judges the untouched draft, including the full tier 1 captures.
3. Each later iteration: patcher candidates → gate → capture → judge → compare against the best so far. Comparison is **lexicographic by tier**:
   - **Worse** if any hard check newly fails (tier 1 hard checks included), or any previously passing defect item now fails **in any view or transition direction**, or the tier 1 pass count drops, or any tier 1 measurement (worst-frame stability change, worst missing-object frames, worst transition spike, peak jerk) gets materially worse, **regardless of tier 2 gains**. A fix in 3D that breaks 2D is a regression; a realism gain that adds shimmer or a morph pop is a regression.
   - **Better** if not worse and either more tier 1 items pass, or the same tier 1 count passes and the tier 1 measurements improve, or tier 1 is equal and more tier 2 items pass, or all counts are equal and pairwise wins exceed losses (tier 1 pairwise first).
   - **Tie or worse:** `git reset --hard <bestCommit>` and add the attempted defects to `triedLedger`. If the same defect has failed twice, tell the patcher to try a structurally different fix.
4. **Escalation, not a human gate.** After `limits.plateauIterations` non-improving iterations in a row, call `lead_architect` with the rubric history, `triedLedger`, best shots next to their references, the `transition-report.json` and stability reports, and the file outline. It returns a diagnosis and a structural plan (refactors, new modules, a different technique, for example unifying the 2D and 3D scene graphs or replacing the morph). The next patcher iteration gets that plan and `patcher.escalatedMaxToolCalls`. If the escalated iteration also fails to improve, stop.
5. **Stop** when every item passes (tier 1 and tier 2), `maxIterations` is reached, the budget is spent, or escalation fails.
6. **Finish automatically.** If the best iteration is strictly better than iteration 0, merge it into `baseBranch` locally with `--no-ff` (never push) and remove the worktree. Other people may have committed to `baseBranch` during the run: if the merge conflicts, abort it, leave `loop/<runId>` unmerged and list the conflicting files in the summary. Otherwise leave the branch unmerged. Either way, write `runs/loop/<runId>/summary.json` (per-iteration rubric counts split by tier, best iteration, open defects, cost, merge result, wall-clock time per stage, 429 count and total cooldown time, cache and reuse hit rates, candidates per iteration, and the tier 1 measurements: worst 2D stability change, objects missing during transitions, worst transition spike, peak camera jerk, for iteration 0 and the best) and print it.
7. **Checkpoint, resume and stalls.**
   - Write `runs/loop/<runId>/state.json` after every stage (capture unit, judge result, patcher candidate, gate, comparison): iteration number, stage, best commit, `triedLedger`, rubric history, spend, escalation state and the IDs of any in-flight background interactions. Writes are atomic.
   - Every stage is idempotent and reuses completed artifacts on disk. `--resume <runId>` reloads `state.json`, recreates the worktree if needed, reattaches to in-flight interactions by ID (or cancels and retries them) and continues from the first incomplete stage. A process crash, a closed laptop or a power loss must not lose more than one stage.
   - A rate-limit or quota wait counts as a **stall** (§0.4). The run keeps waiting and working on other ready tasks while it stalls. If total consecutive stall time exceeds `limits.maxStallMs`, or a `QuotaExhausted` error can't be waited out, write a checkpoint and `summary.json` with `resumable: true` and the exact resume command, leave the worktree and branches in place without merging, and exit with code 75. Do not merge on a stall exit.

## 5. Dashboard

A static `dashboard.html`, regenerated after every iteration:
- **a tier 1 panel at the top:** for 2D stability and each transition (state × direction), iteration 0 | best side by side as videos, the labelled filmstrips, the worst frames, the object-presence timeline (a row per object, a cell per frame, red where missing), the camera jerk plot and the stability difference heatmap
- a rubric grid (items × iterations, with item kind and tier), showing pass/fail per view for items with `views`
- for each fidelity item: reference | iteration 0 | best, side by side, with the best's open gaps
- iteration 0 next to the best for every shot and page shot, and each gameplay video in each view (plus the cinematic video if available)
- each iteration's defects with timestamps, patcher reports per candidate (including which candidate was adopted), diff stat, new regression tests, commit hash and cost; escalation plans inline
- a run-health panel: wall-clock time per stage and per iteration, 429 count and cooldown time, current effective concurrency, cache and verdict-reuse hit rates, and spend against `budgetUsd`

## 6. Tests: `tests/loop.test.ts` (`ORCH_FAKE=1`, offline)

Use a fake scene, `tests/fixtures/loop-scene.html`: a cube with the hooks, including `getObjects` and `setTransition`, and a switchable 2D/3D view with a morph.
1. A missing reference file, a view with no defect or fidelity item, or a missing required aspect (including the tier 1 aspects) fails fast and names it. A missing hook or click selector triggers the bootstrap iteration, and the run exits naming it only if the bootstrap fails.
2. Patcher tools refuse writes to protected paths, baseline tests and paths outside the worktree, and accept new files under `regressionTestDir`. A diff touching a protected path rejects the iteration.
3. A cube that pops in at a known frame **while the camera pans** trips `frameDiff`. The same pan without the pop-in does not.
4. Defect IDs from two judges that both say `D1` survive merging as distinct defects.
5. `uncertain` after the re-ask resolves to fail.
6. A worse or tied iteration resets to the best commit; a plateau triggers escalation; a failed escalation stops the loop; nothing reads stdin.
7. Gameplay steps fire before the first frame at or after their `at`; a `click` on the fake scene's button changes state; a step that throws records a `stepErrors` failure.
8. An item with `views: ["2d","3d"]` that passes in 2D and fails in 3D fails overall, and a change that fixes 3D but breaks 2D counts as worse. A script `expect` over `views` fails when the fake scene switches view partway through.
9. A fake-scene object that appears in one frame during a gameplay step trips `frameDiff`; the same object tweened over 5 frames does not.
10. A `pairViews` item receives matching 2D and 3D images with the same tile marks; an object present in only one view of the fake scene produces a defect naming that tile.
11. A patch touching `outOfScopePaths` is rejected, and a pairwise verdict of an out-of-scope change makes the iteration worse.
12. A failing `reportOnly` item appears in the summary but never becomes a patcher defect and never changes the pass count.
13. Unknown fixture names and steps that change nothing are recorded as `stepErrors`; a false `expect` names its expression.
14. `frameDiff` ignores an instant HUD text change outside the canvas but catches the same change inside it.
15. **Rate limiting.** With `ORCH_FAKE_429=0.5` and a fake clock, a full fake run completes with no call failing; `Retry-After` is honored; the circuit breaker opens after 3 rate-limit 429s in 60s; effective concurrency halves on a 429 and recovers after 20 successes; a 429 never increments a call's failure-retry count.
16. **Quota.** With `ORCH_FAKE_QUOTA_AFTER=<n>` and a reset beyond `maxStallMs`, the run checkpoints, writes `resumable: true` and exits 75 without merging; `--resume` then finishes the run from the first incomplete stage with no repeated spend. A quota reset within `maxStallMs` is waited out and the run continues.
17. **Scheduler.** Global and per-role concurrency caps are never exceeded; higher-priority tasks run before lower ones (tier 1 judging before tier 2); the scheduler rejects a call that would exceed `budgetUsd`.
18. **Cache and reuse.** An identical call hits the cache with no spend; an `uncertain` result is never cached; an unchanged shot reuses verdicts (`reused: true`) with no judge call; a changed rubric hash disables reuse; the golden set bypasses the cache; tier 1 measurements are never reused.
19. **Parallel candidates.** Two candidates receive disjoint defect sets in separate worktrees and ports; one failing its gate doesn't affect the other; two better candidates that cherry-pick cleanly produce a combined candidate that is adopted only if it beats the best single one; all candidate worktrees are removed afterwards.
20. **Parallel capture.** Capture units run concurrently in separate pages and match a serial capture within tolerance; emitting `unit-captured` starts judging before the other units finish; a forced mismatch lowers `capture.workers` and reports a determinism defect.
21. **Early exit.** An iteration that fails a hard check makes no judge calls for that candidate and is recorded as worse.
22. **2D stability.** A fake 2D scene that is idle and deterministic passes `stability2d`; the same scene with a one-pixel tile shift in one frame, a per-frame noise term, a time-driven shadow flicker, or slow drift fails and names the frame and cell; two runs with different play-clock offsets that differ fail; HUD changes outside the masked canvas do not trigger it.
23. **Transition continuity.** A fake morph that keeps every object visible with eased `p` passes `transitionContinuity`; each of these fails and names the object, tile and frame: an object hidden for 3 frames, an object at zero scale for one frame, an object that teleports, a one-frame opacity jump, a material swap pop at the view flip, an object in the state but missing from `getObjects()`, an object in `getObjects()` that is not in the state; both directions are checked; a reversal at p=0.5 that jumps fails; p=0 and p=1 must match the stand-alone views.
24. **Camera smoothness.** A fake camera with eased motion passes `cameraSmoothness`; one with a single-frame stutter, a direction flip or a quaternion sign flip fails and names the frame.
25. **Tier ordering.** An iteration that adds a tier 2 item pass but worsens a tier 1 measurement is **worse** and resets; an iteration that improves a tier 1 measurement with the same pass counts is **better**; the loop does not report done while a tier 1 item is open even if every tier 2 item passes; tier 1 defects are listed first in the patcher context and assigned first when clustering.
26. **Tier 1 tools.** The patcher's `check_transition` and `check_stability` tools return the failing frames and objects for the fake scene's injected defects, and a pass for a clean scene.
27. **Determinism of tier 1 capture.** Two fresh captures of the same transition and the same 2D sequence match within tolerance; a fake scene that uses `Math.random` or wall clock during the morph is reported as a determinism defect.

## Definition of done

1. The offline tests pass.
2. The real golden set has run: `golden.json` holds injected-defect results (including the tier 1 cases), fidelity calibration and tier 1 calibration, with real judge `interactionId`s.
3. A live run completes iteration 0 plus patched iterations until a stop condition, every iteration has gameplay, still, 2D stability and transition verdicts for every view and direction, and the dashboard shows the tier 1 panel, the rubric and the fidelity gaps changing.
4. **At the end, the best iteration has zero tier 1 failures:** the 2D view is pixel-stable at idle, 2D actions animate without pops, and both transition directions from every configured state keep every object present, have no teleports, seams or camera stutters, and match the stand-alone views at both ends; or `summary.json` lists exactly which tier 1 items are still open and why.
5. Every call appears in `runs/orchestrator/trace.jsonl` within `budgetUsd`.
6. The run finished without human input and merged the best iteration if it beat iteration 0, or checkpointed and exited resumably (code 75) after a quota stall longer than `maxStallMs`.
7. A fake run with injected 429s completes without any failed call, and a killed run resumes from `state.json`.
8. `summary.json` and the dashboard report wall-clock time per stage, 429 count, cooldown time, cache and reuse hit rates, candidates per iteration and the tier 1 measurements.
9. Append lessons learned to `AGENTS.md`, commit, and stop.
